## Option D screening

No additional complete architecture met the requested primary-source standard in this bounded review. Current Hugging Face official docs explicitly require a paid PRO/Team/Enterprise plan to create Docker/Gradio compute Spaces even though CPU Basic has no hourly cost; 50 GB default disk is nonpersistent. Static Spaces are free but cannot host this FastAPI API or shared database alone. The narrow free ZeroGPU/Gradio exception is not a native FastAPI replacement. **Excluded**, not offered as a genuinely free deployment. Existing GitHub Pages/static-only layouts also do not supply the API/database.

## Recommended Planning action

Retain A as a conditional first candidate because the implemented Python/API/domain can be reused and local D1 reliability now works. Enable approved official-index access or a complete verified cache only through the supported environment workflow, then prove actual runtime and full-request Free CPU/memory. If those limits fail, reject A without purchasing capacity and investigate B's **actual Free/card terms first**; Neon alone does not establish a free API host. C is a last architecture-change proposal requiring explicit Planning approval and parity/resource proof. Do not start another unbounded failed-index loop or silently ship read-only/local-only persistence.

No public deployment decision is justified until actual account eligibility, payment requirements, CPU/memory, early streamed upload bounds, sustained storage/anonymous availability and real redeployment/recovery are verified. Existing 64 MiB/day app storage containment is not a 500 MB total-retention guarantee.
